# Helper evals

`claude plugin eval` suites for the `add-collection` and `records-doctor`
skills and the `precedent-finder` agent. They cost API calls, so they run by
hand, or from the manually started **Helper evals** workflow
(`.github/workflows/evals.yml`), before a release that changes the helpers.
See [helpers.md](../../docs/specs/helpers.md#testing).

## Running

From the repo root, since cases load both plugins (`card-catalog-helpers`
and `card-catalog-plugin`) and a case can only load plugins under the
target:

```
claude plugin eval . --eval-dir card-catalog-helpers/evals \
  --scaffold --allow-tools Bash Edit Write --max-cost-usd 15
```

- `--scaffold` runs each case's `scaffold.sh`, which builds the fixture repo.
- `--allow-tools Bash Edit Write` lets the skills run the CLI and edit files.
  Bash runs in Claude Code's sandbox, which needs `bubblewrap` and `socat`
  on Linux and refuses to start on some machines (a symlinked Docker
  credential store, for one). The `precedent-finder-*` cases need none of
  the three.
- `card-catalog` on `PATH` at this version (`npm run build:npm && npm
  install -g ./npm`) is the skills' fallback when the session-start message
  gives no CLI path. The sandbox has no network, so `npx` can't download it.
- Add `--case <glob>`, `--runs 1` or `--ablation none` while iterating.

## Layout

Each case is a directory with `prompt.md`, `case.yaml` (naming
`scaffold.sh`) and `graders/`. Runs can't ask the person anything, so the
skills' approval steps end the run: cases check the proposal and that
nothing was written, unless the prompt approves a fix in advance.

`_fixtures/` holds the records the scaffolds copy in, under neutral names
(`adrs/`, not `docs/adr/`) so this repo's own card-catalog doesn't index
them, and `lib.sh`, which every scaffold sources. Indexes are generated by
this repo's CLI when a scaffold runs, never committed.

Results go to `results/`, which git ignores.
