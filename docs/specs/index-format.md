# Index format

Each collection gets two files, written only by card-catalog:

- **`INDEX.md`**, the index: one line per record, for agents to grep and
  people to click through. Its location is the collection's `indexPath`.
- **`index.json`**, card-catalog's own state: the same records plus a
  content hash and amendment time each. It always sits in the collection
  directory, wherever `INDEX.md` goes. Agents aren't pointed at it.

A collection with `indexPath: "none"` gets neither file.

Both files are rebuilt from every record in the collection on each run, and
each is written only if its content changed, by writing a temporary file
next to it and renaming it over the old one.

## `INDEX.md`

```
# ADR index

Generated by the card-catalog plugin from the ADRs in this directory. Edits here are overwritten.
One line per ADR: `label [status] amended | title | summary`. Search it with grep, then open the ADRs that match.

- [ADR-0003](0003-rest-over-graphql.md) [superseded by ADR-0009] 2026-04-01 | REST over GraphQL | We picked REST because …
- [ADR-0009](0009-graphql-gateway.md) [accepted] 2026-04-01 relates-to=ADR-0003 | GraphQL gateway for mobile | …
```

### Header

```
# {name} index

Generated by the card-catalog plugin from the {plural} in {where}. Edits here are overwritten.
One line per {noun}: `{shape}`. Search it with grep, then open the {plural} that match.
```

- `{name}` and `{plural}` come from the profile. `{noun}` is `{name}` if
  it's all capitals, else `{name}` lowercased.
- `{where}` is `this directory` when the index is in the collection
  directory, else the collection directory's path relative to the index,
  in backticks.
- `{shape}` is `label [status] amended | title | summary`. It leaves out
  `[status] ` for a type whose `status` is `null`, and adds `key=value …`
  after `amended` when at least one line in this index has a pair.

The second header line is the marker that identifies a card-catalog index.
`validate` finds [orphaned indexes](#orphaned-indexes) by it.

With the built-in `adr` profile and no `key=value` pairs, the header is the
one card-catalog writes today, except that it says `label` where it said
`ID`.

### Index lines

```
- [{label}]({path}) [{status}] {amended} {key}={value} … | {title} | {summary}
```

| Part | Content |
|------|---------|
| `{label}` | The record's label. |
| `{path}` | The record file's path relative to the index file, with each segment percent-encoded as `encodeURIComponent` does. |
| `[{status}]` | The status. If the profile's `showLink` names a link type for this status and the record has that link, `{status} by {target}`, as in `superseded by ADR-0009`. Left out, with its trailing space, for a type whose `status` is `null`. |
| `{amended}` | The date part (`YYYY-MM-DD`, UTC) of `amendedAt`. |
| `{key}={value}` | One pair per non-empty field, in profile order, then one per link type with targets, in profile order. A link the status already shows is left out. |
| `{title}` | The title on one line. |
| `{summary}` | The summary, cleaned and cut to 280 characters. |

Pair values:

- several link targets are joined with `,`: `relates-to=ADR-0002,ADR-0005`;
- a value containing whitespace, `"`, `|` or `\` is wrapped in double
  quotes, with `"` and `\` escaped by a backslash:
  `follows="Postmortem 2026-09-14-db-outage"`.

In `{title}` and `{summary}`, `|` is written as `\|`, so splitting a line on
` | ` always finds three parts. Markdown renders `\|` as `|`.

### Order

Records without a series come first, then each series in alphabetical
order. Within each group, records sort by number if the ID pattern has
`{number}`, then by ID, then by file path.

## Collections with no records

card-catalog doesn't create an index for a collection with no records, so a
glob matching a new, empty directory doesn't leave files in it. If a
collection that has an index loses its last record, the index is rewritten
with the header only and an empty `records` list. Its files are never
deleted.

## `index.json` version 3

One record per line keeps git diffs readable:

```
{"version":3,"generatedBy":"card-catalog","type":"adr","records":[
{"id":"0003","label":"ADR-0003","slug":"rest-over-graphql","title":"REST over GraphQL","status":"superseded","summary":"We picked REST because …","file":"0003-rest-over-graphql.md","links":[{"type":"superseded-by","target":"ADR-0009","file":"0009-graphql-gateway.md"}],"contentHash":"9f2c4e1ab07d3355","amendedAt":"2026-04-01T12:00:00.000Z"},
{"id":"0009","label":"ADR-0009","slug":"graphql-gateway","title":"GraphQL gateway for mobile","status":"accepted","summary":"…","file":"0009-graphql-gateway.md","date":"2026-04-01","tags":["api"],"contentHash":"1b397289f97f2b39","amendedAt":"2026-04-01T12:00:00.000Z"}
]}
```

The file is `{` + top-level keys + `"records":[`, then one record per line
joined by `,\n`, then `]}` and a newline. Records are in index order.

| Top-level key | Meaning |
|---------------|---------|
| `version` | `3` |
| `generatedBy` | `"card-catalog"` |
| `type` | The collection's record type |
| `records` | The records |

| Record key | Present | Meaning |
|------------|---------|---------|
| `id` | always | The ID, a string |
| `label` | always | The label |
| `series` | in a series | The series, lowercased |
| `slug` | when the filename has one | The slug |
| `title` | always | |
| `status` | types with a status | |
| `summary` | always | May be `""` |
| `file` | always | Path relative to the collection directory |
| `date` | when found | As written |
| `tags` | when found | Array of strings |
| `links` | when any | `[{ "type", "target", "file"? }]`; `file` is relative to the collection directory and present when the target was found as a file |
| `fields` | when any | `{ "<name>": "<value>" }` |
| `contentHash` | always | See [Amendment times](#amendment-times) |
| `amendedAt` | always | UTC ISO 8601 |

Keys appear in the order of this table. Absent keys are left out, never
written as `null`.

## Amendment times

`amendedAt` is when a record's content last changed. These rules are
unchanged from version 2:

- `contentHash` is the first 16 hex characters of the SHA-256 of the file's
  content, after turning `\r\n` and `\r` into `\n`, removing trailing spaces
  and tabs from each line, and removing trailing whitespace at the end.
- If the previous `index.json` has an entry for the same `file` with the
  same hash, `amendedAt` stays the same.
- If the hash differs, `amendedAt` is the current time.
- If there's no previous hash for the file, `amendedAt` is the file's last
  commit date, or the current time if git doesn't track the file.

A record that fails to parse keeps its previous entry, with the new hash and
`amendedAt`, so a broken edit doesn't lose its line.

## Reading older indexes

From a previous `index.json`, card-catalog reads only each record's `file`,
`contentHash` and `amendedAt`. Everything else is rebuilt from the records.
Versions 1 and 2 keep their records under `adrs` rather than `records`.
Version 1 has no hashes, so its amendment times are backfilled from commit
dates.

An older `index.json` is rewritten as version 3 on its next write, so every
existing ADR `index.json` changes once. Until then, an older version doesn't
make the index count as out of date: it's
[current](#current-and-stale-indexes) if `INDEX.md` is.

An `index.json` with a version above 3 was written by a newer card-catalog.
It's never overwritten. Hooks log a warning, `reindex` skips the collection,
and `validate` reports `newer-index` (an error).

## Current and stale indexes

An index is **current** when a rebuild would write exactly the `INDEX.md`
and `index.json` already on disk, allowing for an older `index.json`
version as above. Otherwise it's **stale**. The session-start message marks
stale indexes, and `validate` reports them as errors.

## Orphaned indexes

An orphaned index is a card-catalog `INDEX.md` or `index.json` that no
current collection writes. Typically its directory stopped being a
collection, or its `indexPath` changed. card-catalog never deletes files, so
orphans stay until someone removes them.

A markdown file is a card-catalog index if one of its first five lines
starts with `Generated by the card-catalog plugin` or
`Generated by the adr-index plugin`. A file named `index.json` is one if its
top-level `generatedBy` is `card-catalog` or `adr-index`. Files under
ignored paths and in nested repos aren't checked. Outside a git repo, the
search skips the directories that default discovery skips and goes at most
8 levels deep, so a session started outside any repo stays fast. `validate` checks every markdown file; the
session-start message checks only files named `INDEX.md` and `index.json`,
to stay fast. See [validate.md](validate.md#indexes).
